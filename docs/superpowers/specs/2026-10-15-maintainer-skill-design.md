# Скилл мейнтейнера Symfony Best Practices

Запрос: сопровождение репозитория, обновление источников, проверки и выпуск релизов.

## Решение

Один repository-local `symfony-skill-maintainer` в `.agents/skills/` с коротким английским входом, Codex UI metadata и тремя адресными справочниками: sources, checks, releases. `.codex/skills/` и `.claude/skills/` содержат относительные symlinks на канонический каталог. `AGENTS.md` направляет работу с репозиторием в этот скилл; README сохраняет текущие язык и стиль.

Альтернативы: четыре самостоятельных скилла дублируют общий контекст; один большой SKILL.md загружает процедуры публикации даже для небольшого изменения. Короткий вход со справочниками соответствует структуре существующего пакета.

## Границы

`skills/symfony-best-practices/` — распространяемый продукт. Новый скилл обслуживает его репозиторий и не входит в tar.gz/zip. Его добавление не меняет VERSION, донорские commits или документацию Symfony. Существующие 31 справочник и schema 3 сохраняются.

Основной checkout остаётся без изменений. Реализация идёт в отдельной ветке; итоговая основа — `origin/main` на `54c7b20`, с полным пакетом и английским README. Merge, push, tag и публикация не входят в этот запрос.

## Контракты

- Источники: repository-qualified donor identity, pinned SHA, raw-file SHA-256, лицензии и адресная карта покрытия обновляются вместе. Смена Symfony baseline/date или покрытия требует сверки ограничений scripts/tests.
- Проверки: штатные Python-команды, сверка четырёх source checkout, согласованность metadata, links/discovery, сравнение архивов и checksums.
- Релизы: выбранный commit и версия, синхронизация version fixtures, чистая сборка, terminal CI этого SHA, существование remote tag, точные assets и проверка скачанных байтов. Публикация выполняется только в рамках поручения на выпуск; подготовка остаётся полезной самостоятельно.
- Исторические отчёты не переписываются как новое доказательство. Тесты, CI, source verification и опубликованный release имеют отдельные статусы.

## Проверка результата

Три структурных теста до создания скилла должны обнаружить отсутствие входа, справочников и aliases. После реализации штатная unittest discovery запускает их в существующем CI. Сценарная оценка независимым агентом проводится до и после добавления скилла; она проверяет решения и routing, а не Symfony runtime. Полная сборка должна содержать только исходный product skill, побайтово равный каноническим файлам.
